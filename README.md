# Gentle King

The ministry site for Gentle King. Reformed doctrine, the whole gospel, free books,
reading and study resources, and the Bible study software being built.

It is a plain static site. No framework, no npm, no dependencies. GitHub Pages
serves the `.html` files at the top of this repository exactly as they are.

---

## Editing the site

There is one small build script so that the header, the footer, and all the page
metadata live in a single place instead of being copied into seven files.

**To change the words on a page**, edit the matching file in `content/`, then run:

```
python3 build.py
```

That rewrites the `.html` files at the top of the repo. Commit those files and push.
GitHub Pages never runs the script, it only serves what you commit.

**To change the header, the footer, the navigation, the page titles, or the social
preview text**, edit `build.py` and run it again.

**To change how the site looks**, edit `assets/css/site.css`. The colors, the fonts,
and the spacing are all set as variables near the top of that file, so a small edit
there changes the whole site at once.

**Before you push**, run the checker. It catches broken HTML, links pointing at
files that are not there, duplicate section ids, and stray punctuation.

```
python3 check.py
```

## What is where

```
build.py                the builder. Wraps content in the shell.
check.py                looks over the built pages for mistakes.
.github/workflows/      builds, checks, and publishes on every push to main.
content/                the words. One file per page. Edit these.
assets/css/site.css     the whole design. Colors and fonts at the top.
assets/js/site.js       theme switch, mobile menu, on-this-page links.
assets/img/             the crown mark, the favicons, the social card.
assets/books/           where finished book files go. Empty for now.
index.html …            generated. Do not hand edit, they get overwritten.
404.html                hand written and self contained. Edit directly.
sitemap.xml  robots.txt generated by build.py.
.nojekyll               tells GitHub Pages to serve the files as they are.
```

## Adding a book

1. Put the file in `assets/books/`, for example `assets/books/assurance.pdf`.
2. Open `content/books.html` and find the card for that book.
3. Replace the line saying the file is not posted yet with a download link, like this:

```html
<a class="btn btn-primary" href="assets/books/assurance.pdf" download>Download the PDF</a>
```

4. Remove the `<span class="tag tag-soon">Coming</span>` from that card.
5. Run `python3 build.py`, then commit and push.

## Posting the study app download

1. Open `content/software.html` and find the section with `id="download"`.
2. Replace the callout that says there is nothing to download with a real button.
3. Run `python3 build.py`, then commit and push.

## How it goes live

Pushing to `main` publishes the site. A workflow in `.github/workflows/pages.yml`
runs `build.py`, then runs `check.py`, and only publishes if the checker passes.
So a broken link or a mangled tag stops the deploy instead of going out to
readers. It also switches Pages on by itself the first time it runs, so there is
nothing to set in the repository settings.

To watch a deploy, open the **Actions** tab. A green check means it is live.

If you ever point a custom domain at the site, do two things. Create a file named
`CNAME` at the top of the repo containing only the domain, and change `SITE_URL`
near the top of `build.py` to match. Then rebuild. Every link inside the site is
relative, so nothing else has to change.
